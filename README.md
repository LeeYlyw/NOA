# NOA

진행 현황, 시연 범위와 검증 상태는 `PROJECT_STATUS.md`를 먼저 확인하세요.

게임은 `Assets/1.Scenes/MapGeneration_Test.unity`에서 실행합니다 (`offlineMode = false`).
로컬 서버가 없으면 게임이 `GameServer.exe`를 창 없이 실행하고 로비에 접속합니다.
같은 실행 파일을 두 번 실행하면 같은 로비에 접속합니다. 플레이어별로 따로 빌드할 필요가 없습니다.
서버가 먼저 접속한 클라이언트에 Player 1, 다음 클라이언트에 Player 2를 배정합니다.
번호 수신 전에는 직업 선택·준비·게임 패킷 전송을 대기하며, 조작 캐릭터·카메라·UI도 배정된 번호에 맞춰 연결됩니다.
직업은 접속 순서와 관계없이 로비에서 선택합니다.
감지자·탐색자·치유자·러너는 각각 기존 플레이어 1·2·3·4 프리팹 외형으로 생성됩니다. 동시에 조작하는 인원은 여전히 두 명입니다.
각자 직업을 선택하고 준비를 누르면 방장이 게임을 시작할 수 있습니다 (현재 정원 2명). 단서를 모으려면 두 명 중 적어도 한 명은 탐색자여야 합니다.
직업을 바꾸면 준비가 취소됩니다. 시작 후 기존 맵 생성과 스폰이 실행됩니다.

서버 코드를 변경한 뒤에는 `powershell -NoProfile -ExecutionPolicy Bypass -File Server/BuildServer.ps1`로 x64 Release 서버를 빌드합니다.
빌드 결과는 `Server/x64/Release/GameServer.exe`와 배포용 `Server/GameServer.exe`에 놓입니다.
배포 시 Server 폴더도 함께 전달해야 합니다.
서버를 별도로 수동 실행할 필요는 없습니다. 기존 서버가 실행 중이면 새 코드로 재시작해야 합니다.
다른 PC에서는 같은 빌드를 복사해 실행 인자 `-serverIP 서버PC의_IP`를 붙여 접속합니다. 예: `NOA.exe -serverIP 192.168.0.10` (실제 실행 파일명과 서버 PC 주소로 교체). 서버 PC에서는 기본 주소 `127.0.0.1`로 실행하면 됩니다. 다른 포트를 쓸 때는 `-serverPort 7777`도 지정할 수 있습니다. 빌드의 실행 파일 옆에 `Server/GameServer.exe`를 두어 서버 PC에서 자동 실행되도록 합니다.
로비에서 방장이 나가면 남은 플레이어에게 방장 권한이 넘어갑니다.
게임 진행 중 연결이 끊어지면 결과 화면에서 로비로 돌아가 재접속합니다. 빈 로컬 로비 서버는 30초 후 종료됩니다.
로비 UI는 우선 기능 확인용 영어 기본 화면으로 구성되어 있습니다.

## 협동 색·도형 퍼즐

두 플레이어가 게임을 시작하면 시작 지점 근처에 파란색·주황색 발판이 생성됩니다.
Player 1은 파란 발판, Player 2는 주황 발판에 올라갑니다. 둘 다 올라가면 Player 1에게만 정답 문양이 보이고 Player 2에게는 네 가지 후보가 보입니다.
Player 1이 1라운드에는 외곽 모양, 2라운드에는 모양과 색, 3라운드에는 중앙 표시까지 설명하고 Player 2가 숫자키 1–4로 선택합니다.
세 라운드 정답을 맞히면 잠긴 방 문이 열립니다. 맵에 흩어진 단서 2개와 방 안의 단서 1개를 탐색자 직업이 수집하면 임무가 완료됩니다. `J`로 양쪽의 공유 단서 기록을 볼 수 있습니다.
오답은 잠시 후 재시도할 수 있으며 한 명이라도 발판을 벗어나면 선택이 막힙니다.

개발 환경에서 MSPDB140.DLL 버전 오류가 발생하면 서버 빌드 명령 전에 PowerShell에서 `$env:_LINK_ = "/DEBUG:NONE /INCREMENTAL:NO"`를 설정하여 디버그 심볼 없이 빌드할 수 있습니다.
