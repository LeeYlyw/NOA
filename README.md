# NOA

진행 현황, 시연 범위와 검증 상태는 `PROJECT_STATUS.md`를 먼저 확인하세요.

게임은 `Assets/1.Scenes/MapGeneration_Test.unity`에서 실행합니다 (`offlineMode = false`).
지정한 PC에서 서버를 먼저 실행하고, 클라이언트의 로비에서 같은 서버 주소로 접속합니다.

1. 서버 빌드: `powershell -NoProfile -ExecutionPolicy Bypass -File Server/BuildServer.ps1`. 설치된 C++ 빌드 도구를 자동 선택합니다. 특정 도구를 쓸 때만 `-PlatformToolset v143` 또는 `v145`를 지정합니다.
2. 서버 PC에서 `Server/StartServer.ps1`을 실행하면 접속용 IPv4 주소를 안내하고 서버를 시작합니다. `Server/GameServer.exe`를 직접 실행해도 됩니다. TCP 7777로 접속을 기다리며 빈 로비에서도 종료되지 않습니다.
3. 게임 로비에서 서버 주소를 입력하고 접속합니다. 같은 PC에서는 `127.0.0.1`, 다른 PC에서는 서버 PC의 IPv4 주소(`ipconfig`로 확인)를 입력합니다. 마지막 주소는 저장됩니다. `-serverIP` 실행 인자는 저장된 주소보다 우선합니다.
4. 같은 네트워크의 다른 PC가 접속하려면 서버 PC 방화벽에서 GameServer.exe의 TCP 7777 수신을 허용합니다. 외부 네트워크 접속은 별도 라우터/주소 설정이 필요합니다.
5. 2~4명이 서로 다른 직업을 선택하고 모두 준비하면 방장이 시작합니다.

서버 실행 PC가 서버의 CPU·메모리·네트워크 사용을 부담합니다. 해당 PC에서 게임도 함께 실행할 수 있습니다. 클라이언트는 서버를 자동 실행하지 않으며, 게임 빌드에는 서버가 포함되지 않습니다. 서버 코드 변경 시 별도로 빌드하고 실행 중인 서버를 교체하세요.
한 번에 한 팀을 지원합니다. 게임 중 신규 접속은 거절합니다. 결과 화면에서 전원 재시작에 동의하거나 한 명이 연결을 끊으면 기존 세션을 종료하고 같은 서버가 새 로비를 받습니다. 클라이언트는 로비 복귀 후 접속 버튼으로 다시 접속합니다. 서버 종료는 실행 창을 닫아 처리합니다.

## 협동 색·도형 퍼즐

두 플레이어가 게임을 시작하면 시작 지점 근처에 파란색·주황색 발판이 생성됩니다.
Player 1은 파란 발판, Player 2는 주황 발판에 올라갑니다. 둘 다 올라가면 Player 1에게만 정답 문양이 보이고 Player 2에게는 네 가지 후보가 보입니다.
Player 1이 1라운드에는 외곽 모양, 2라운드에는 모양과 색, 3라운드에는 중앙 표시까지 설명하고 Player 2가 숫자키 1–4로 선택합니다.
세 라운드 정답을 맞히면 잠긴 방 문이 열립니다. 맵에 흩어진 단서 2개와 방 안의 단서 1개를 탐색자 직업이 수집하면 임무가 완료됩니다. `J`로 양쪽의 공유 단서 기록을 볼 수 있습니다.
오답은 잠시 후 재시도할 수 있으며 한 명이라도 발판을 벗어나면 선택이 막힙니다.

개발 환경에서 MSPDB140.DLL 버전 오류가 발생하면 서버 빌드 명령 전에 PowerShell에서 `$env:_LINK_ = "/DEBUG:NONE /INCREMENTAL:NO"`를 설정하여 디버그 심볼 없이 빌드할 수 있습니다.

## 고정 서버 회귀 검사

서버를 빌드한 후 실행합니다. 7777 포트가 이미 사용 중이면 기존 서버를 건드리지 않고 중단합니다.
- `Server/TestDedicatedSession.ps1`: 빈 로비 32초 유지, 2→4→2인 게임 시작, 진행 중 접속 거절, 연결 종료 후 다음 로비.
- `Server/TestDedicatedMatch.ps1`: 같은 프로세스에서 2인·4인 맵 준비, 퍼즐 3라운드, 단서 3개 수집, 클리어, 전원 재시작 투표.
이 검사는 TCP 가상 클라이언트를 사용합니다. Unity 화면이나 실제 두 PC 플레이를 검증하지는 않습니다.
