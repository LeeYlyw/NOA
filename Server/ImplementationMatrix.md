# 10월 28일 시연 구현 점검 — 서버 × 클라이언트

기준: 2026-10-25 `codex/demo-flow-p0` 코드. `[x]`는 **코드가 존재함**을 뜻하며 Unity 화면이나 실제 두 PC 통과를 뜻하지 않는다. `[ ] 구현`은 코드 보강이 남은 항목, `[ ] 확인`은 코드는 있으나 실행 확인이 남은 항목이다. `V0`은 시연 전 필수 확인, `P1`은 시연 흐름 결함이 나타나면 우선 수정, `P2`는 이후 보강이다.

범위: 두 명이 한 스테이지를 완주한다. 4개 직업/외형은 4인 동시접속 요구가 아니다. 도플갱어는 이번 범위에서 제외했고, 별도 탈출 단계는 결정되지 않았다. 애니메이션 클립·Animator Controller는 팀원 담당이다.

## 남은 구현의 권장 순서

1. **P1 즉시 보강:** 맵 생성 실패를 즉시 결과 화면에 전달한다. 치유 승인/거절과 미믹 동료 교차 피격은 코드 보강 및 로컬 소켓 검사를 마쳤으며, 실제 두 PC 확인이 남았다.
2. **V0 시연 흐름 확인:** Unity 화면과 실제 두 PC의 한 판 완주. 문/몬스터 이동, 미믹 교차 피격, 텔레포트, 아이템 획득 시 시점 튐이 재현되면 해당 결함을 먼저 수정한다.
3. **P2 화면·콘텐츠:** 로비/결과 `OnGUI` 통일, 발판→잠긴 방 안내, 결과 연출, 필수 아이템 위치 규칙과 단서 정식 에셋을 차례로 보강한다.
4. **P2 서버 신뢰 경계:** 아이템 배치·획득 위치 대조와 일반 이동 검증은 기본 아이템 사용/몬스터 AI의 재구현과 구별해 진행한다.

## 서버

### 1. 플레이어

- [x] 2개 접속 슬롯, 방장·준비·4개 직업 선택, 탐색자 없는 시작 거절 (`GameServer.cpp` 로비 루프).
- [x] 플레이어 1·2의 이동/행동 상태 중계, 서버 HP·사망 상태, 전멸 패배 확정.
- [x] 치유자 직업·거리·회복량 상한·10초 쿨다운, 아이템 부활 대상·거리 검사.
- [x] 치유 스킬은 한 번의 서버 판정으로 근접한 생존 동료/본인을 최대 30 HP 회복한다. 실제 회복한 대상이 있을 때만 서버 10초 쿨다운을 시작하고 시전자에게 성공/거절 패킷을 보낸다. 클라이언트는 성공 응답 후에만 쿨다운을 표시한다.
- [ ] **구현 P2:** 일반 이동 좌표의 속도·내비게이션 타당성 검사. 현재 서버는 숫자 형식과 사망 여부는 검사하지만 이동 경로 자체는 클라이언트 좌표를 따른다.
- [ ] **확인 V0:** 직업 조합, 두 화면 위치·걷기/달리기/점프/웅크리기, 피격·사망·부활 상태 일치.

### 2. 몬스터

- [x] 시야형·소리형 순찰→감지/소리 조사→추적→수색→공격을 서버에서 계산; 1m 격자 A*와 벽·닫힌 문 경로 차단.
- [x] 공격 상태를 먼저 보내고 0.35초 뒤 생존·거리·시야를 재검사해 피해 확정; 양쪽에 상태·피해·확정 HP 전송.
- [x] 오브젝트 미믹의 경고/발사는 클라이언트 1에서 실행한다. 어느 생존 동료든 자신의 화면에서 피격을 신고할 수 있고, 서버는 탄도·도달 거리·앞선 동료·중복을 검사한 뒤 HP를 확정한다. **미믹 AI 전체와 월드 Collider 판정이 서버 소유인 것은 아님.**
- [ ] **확인 V0:** 미믹의 동료 차단·벽 차단·회피를 실제 두 PC에서 재현하여 위치 오차와 패킷 지연으로 판정이 어긋나지 않는지 확인한다.
- [ ] **확인 V0:** 좁은 통로·일반 문·퍼즐 문에서 관통/멈춤, 공격 준비와 피해 시점, 미믹 경고·발사·피격을 두 화면에서 관찰.

### 3. 아이템

- [x] 아이템 ID별 획득 1회, 소유자·6칸 한도·사용 1회·회복/은신/부활/텔레포트 조건 검사, 성공/거절 패킷.
- [x] 단서는 탐색자만 수집 가능하며 서버가 공유 수와 3개 클리어를 확정.
- [ ] **구현 P2:** 서버가 맵의 아이템 ID·종류·위치 목록을 양쪽 제출값과 대조하고 획득 거리를 검사. 현재 최초 획득 요청의 ID/종류는 클라이언트 신고를 신뢰한다. 기존 소유·소비 검사를 재구현하는 작업이 아니다.
- [ ] **확인 V0:** 6칸 포화, 거절 뒤 재시도, 동시 접촉, 네 사용 아이템의 소비·HP·효과가 양쪽에 일치.

### 4. 맵

- [x] 양쪽이 제출한 시드 기반 내비게이션 격자·몬스터 스폰·퍼즐 문·일반 문·발판 위치를 비교하고 오류/준비 상태 방송.
- [x] 닫힌 일반 문과 퍼즐 문을 경로 차단에 반영하고 개폐 후 몬스터 경로를 재계획.
- [ ] **구현 P1 조건부:** 1m 격자는 Unity Collider의 근사다. 실제 문 폭·좁은 길에서 관통이 나오면 문 반경/경로 규칙 조정.
- [ ] **확인 V0:** 여러 맵 시드에서 양쪽 같은 배치·문 상태, 맵 준비 실패 메시지, 막힌 통로 없는 이동.

### 5. 콘텐츠

- [x] 두 발판의 서버 거리·높이·생존 확인, 이탈/사망 시 해제, 3단계 문양 정답·오답·재시도·잠긴 방 개방.
- [x] 일반 단서 2개와 잠긴 방 단서 1개 수집 시 승리, 전원 사망 시 패배, 두 명 재시작 투표.

- [x] 이동·소음·행동 상태 송신, 원격 위치/애니메이션 상태 수신, 사망·HP·부활 반영. 마우스 회전의 프레임 시간 의존은 수정.
- [ ] **확인 V0:** 4개 직업을 두 슬롯에 번갈아 선택해 외형, 카메라, 이동·피격·사망 모션, 감지음·치유·러너 스탯 확인. 프리팹 참조는 정적으로 확인했지만 Unity 화면은 미확인.

- [x] 시야형·소리형은 멀티에서 로컬 AI를 끄고 서버 상태로 위치/동작을 갱신; 오프라인은 기존 Unity AI 사용.
- [x] 오브젝트 미믹의 클라이언트 1 감지·경고·발사, 반대 화면 발사 동기화, 각 클라이언트의 자기 플레이어 피격 요청; 상태별 효과음·발걸음 제공.

- [ ] **팀원 연계:** 공격 접촉 프레임은 서버 0.35초 피해 시점과 맞춰야 한다. 모션 파일은 이 작업에서 수정하지 않는다 (`PresentationAnimationNotes.md`).

### 3. 아이템

- [ ] **확인 V0:** 포화 인벤토리의 월드 아이템 보존, 실패 시 아이템 미소비, 동시 획득, 획득 순간 시점/프레임 안정성.
- [ ] **구현 P2:** 필수 아이템의 구역별 접근성·위험도 규칙. 현재 최소 수량만 보장하고 위치는 무작위다.

- [ ] **확인 V0:** 여러 시드의 실제 방/복도 접근성, 두 플레이어 시작 위치·몬스터 거리, 문 회전과 텔레포트 목적지 안전성.

## 검증 기준과 다음 행동

- **자동 완료:** C# 컴파일 오류 0개, C++ Release 빌드, 로컬 두 소켓의 내비게이션·몬스터 공격/치유·미믹 교차 피격 smoke 및 기존 3라운드 퍼즐 smoke가 기록돼 있다. 변경 범위에 맞는 검사만 다시 수행한다.
- **Unity/두 PC 미완료:** Unity 배치 실행은 LicensingClient IPC 시간 초과(코드 199)였다. 실제 화면과 두 PC 확인 결과를 임의로 완료 표시하지 않는다.
- **첫 순서:** Unity 실행 가능 환경에서 V0 항목을 확인한다. 실패가 나오면 해당 영역의 P1을 먼저 고친다. 서버 아이템 신뢰 경계와 미믹 차단은 이미 끝낸 기본 획득/동기화 작업과 구별한다.
