# 연출 보강과 팀원 모션 작업 메모

현재 연출은 C# 표시 코드와 C++ 서버 판정을 사용합니다. 애니메이션 클립, Animator Controller, 모델, 프리팹, 공유 머티리얼은 수정하지 않았습니다.

## 구현한 연출

- 서버에서 확정한 발판 준비/해제, 퍼즐 단계, 오답, 잠금 해제에 안내 문구와 음향을 연결했습니다. 발판 색과 조명은 같은 상태에서 갱신합니다.
- 단서 수 증가와 최종 클리어에 공유 알림을 표시합니다. 시간 정지 후에도 알림은 표시됩니다.
- 시야형·소리형은 서버 상태(멀티) 또는 기존 로컬 AI 상태(오프라인)를 받아 발견/수색/공격 음향을 재생합니다. 발걸음은 실제 이동 거리에 따라 재생합니다.
- 미믹은 기존 경고 상태와 실제 발사 횟수에 음향을 연결합니다.
- 몬스터 음향은 거리 감쇠와 간단한 장애물 감쇠를 적용합니다. 반복 수신한 같은 상태/공격 번호로는 중복 재생하지 않습니다.
- 현재 음향은 코드로 만든 짧은 기본 효과입니다. MonsterPresentation의 discoveryClip/searchClip/attackClip/footstepClip에 팀의 정식 효과음을 지정하면 기본 효과 대신 사용합니다. 실제 플레이에서 음량과 분위기 조정이 필요합니다.

## 팀원 모션 작업 시 추천할 항목 — 아직 적용하지 않음

1. 순찰 걷기와 추격 이동을 구분할 클립 또는 블렌드 구간: 서버 속도는 이미 다르게 보내지만 실제 발 디딤과 이동 속도가 맞는지는 두 화면에서 확인해야 합니다.
2. 발견 시 짧은 반응, 마지막 위치에서 주위를 살피는 수색 모션: 상태 데이터는 있으므로 클립이 준비되면 전환을 연결할 수 있습니다. 지금 모델을 돌리거나 뼈를 움직이는 연출은 추가하지 않았습니다.
3. 공격 준비–접촉–회복 구간: 서버는 공격 상태와 번호를 먼저 보내고 0.35초 후 거리·시야·생존 상태를 다시 검사해 피해를 확정합니다. 팀원이 공격 클립의 접촉 프레임을 정하면 이 0.35초와 맞춰야 합니다. 클라이언트 애니메이션 이벤트만으로 피해를 확정하면 안 됩니다.
4. 공격 중 추적 전환, 회전, 이동 정지에서 모션이 끊기는지 확인: Animator 전환 시간과 인터럽트 조건은 팀원이 조정할 대상입니다.
5. 미믹의 경고–발사–재대기 모션: 기존 상태와 발사 이벤트에 연결하면 양쪽 클라이언트의 연출 기준을 맞출 수 있습니다.
6. 플레이어 3·4 프리팹을 치유자·러너 직업에서 실제 생성하도록 연결했습니다. 기존 Animator Controller와 클립은 건드리지 않았습니다. 팀원은 두 프리팹의 걷기·달리기·점프·피격·사망 전환이 양쪽 화면에서 1·2번과 같은 상태 패킷에 반응하는지 확인해야 합니다.

이 항목들은 클립을 직접 재생해 확인한 결함 목록이 아니라, 현재 상태/공격 코드와 연결하기 위해 필요한 모션 제작 항목입니다.
